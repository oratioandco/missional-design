Decision worksheet

A decision you can explain: a short worksheet for a product review, design brief or AI-assisted build.

  1. Name the person and task.

    Who is doing what, in which situation? State the intended benefit without a business metric standing in for it.

  2. Examine the default.

    What behaviour does it encourage? Which theological or organisational assumption does it carry? Consider whether that intention is shared by the person using the product.

  3. Choose two plausible options.

    Use a linked pattern or guide. Explain where each helps and whom it excludes.

  4. Name the cost.

    Consider attention, money, disclosure, accessibility and human responsibility. Which burden is justified, and which is avoidable?

  5. Define the boundaries.

    What happens on failure, refusal, exhausted credits, interruption and leaving? What will be recorded or shared?

  6. Choose and test.

    Write a provisional decision, the evidence behind it, a realistic test and the result that would make you change it. Name an owner and review date.

Example: an evening reminder

Decision: offer a user-set evening reminder with pause, neutral preview and direct passage entry. Compare it with a weekly digest. Measure whether participants find it useful and can control it; do not use opens as a measure of faithfulness. Revisit if duplicate messages or pressure are reported.

For an AI-assisted build

Give your coding assistant the chosen pattern URL, intended behaviour, data exclusions and failure states. Ask it to implement the smallest complete flow and demonstrate cancellation, accessibility and recovery. Inspect the result; generated code is not evidence that the design works.
